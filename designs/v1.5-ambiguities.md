# v1.5 Design Implementation — Ambiguities & Judgment Calls

Every place the design's logic was unspecified, contradictory, or collides with the current
build — with the decision taken. All cheap to flip. (Earlier draft superseded 2026-08-05 after
the full design file + saved theme landed; the star-economy row answered several old items.)

## Theme & type

1. **Saved theme wins over raw markup.** The markup is clay/cream; your saved props re-theme
   it teal/mint (`#2C6E6A` / `#E7EFEC`, sat 50%, +5 lightness, Gabarito titles, soft-fade list
   clips). I implemented the *computed* palette (spec §0) — the app is NOT themable at
   runtime; the design page's theming machinery is a design-time tool. If you later want
   user-facing themes (the ★400 "theme" purchase), the token file is the single place values
   live.
2. **Ground collapse at +5 lightness.** The algorithm sends three light grounds
   (`#FDFBF7`, `#FAF6EF`, `#FBF7F0`) to pure white, killing the card-edge and rail
   distinctions the design itself relies on. I kept one-step separations (`#FFFFFF`,
   `#FDFEFE`, `#FAFCFB`) so edges/rails still read. Flip to literal white if you prefer.
3. **Gabarito weights:** design maps ≥500→500, <500→400. Card/screen titles all render 500.
4. **Newsreader appears in the markup but your saved `titleFont` is Gabarito** — Gabarito
   implemented; Newsreader not shipped (one less font family).

## Star economy

5. **Unsized tasks.** The economy defines only ★5/★20. Unsized cards: valued at 5 (quick-win
   value) until sized; banking cap 5; no size caps label on the rail (rail shows due +
   contexts only). The AI/brain-dump/triage flows push toward sized tasks anyway.
6. **Banked semantics in the ledger.** Step completion writes +1/+2 `subtask_completed` rows
   (size-dependent, capped at 5/10 banking steps per task); the home/working "banked" figure
   is the net of those rows for tasks still pending/in_progress. Completion award = value +
   live badge − banked-for-that-task, floored at 0 (over-banked tasks never award negative).
   Undo completion removes only the completion rows (banked survive, counter reverts).
7. **"+N today" counts owned stars only** — banked rows are excluded from the today delta
   until conversion (per S·WHAT THINGS MEAN: "+1 today never includes banked"). The today
   figure therefore moves by the full converted amount at completion.
8. **Bonus window "until" copy:** `BONUS UNTIL <weekday of window close>` (deadline − 2
   days; or the capped end for short-notice tasks). Window state is derived from
   deadline/createdAt (no persistence); changing the deadline re-derives — a fresh deadline
   gets a fresh window ("offered once" reads as once per deadline).
9. **Don't-skip offer state** lives in a LOCAL-ONLY `task_offers` table (per-device
   mechanic — never synced, no Postgres mirror; same rationale as subtasks); coin flip =
   50%; evaluated when an eligible card reaches the top with no live offer anywhere ("one
   live offer at a time" read as global). Re-offer cooldown after eroding to 0: 3 days.
   Age trigger reuses the stale threshold (≥7 days unengaged).
10. **Offer + window on the same card:** larger badge wins (design rule); the loser isn't
    consumed — the offer erodes only on passes made while it's the displayed badge.
11. **Cut loose award** (+3) unchanged — Row E doesn't address it. Not a multiple of five;
    kept as the existing owner-approved value.
12. **Triage queue-clear +5 once/day:** awarded when the queue count reaches 0 by a Save/
    confirm action (not by cut-loose/archive emptying it) and no award was made that local
    day. Ledger action `triage_confirmed` reused with amount 5 (per-card +1 awards removed).
13. **Spending, balance vs lifetime, prices** — explicitly future in the design; not built.
14. **Old bonuses removed:** rank-based urgency bonus and early-completion bonus are gone;
    the card value preview and completion payouts use the new model everywhere (star-log
    history rows are untouched).

## Home / deck

15. **Context-bar session expansion:** non-persisted zustand flag; auto-expands on first
    home mount per app launch. (Cold start = new session.)
16. **Collapsed bar with NO contexts selected:** design doesn't show it; I show all five
    glyphs dimmed (bar keeps its shape; nothing-selected = unfiltered).
17. **`Either` vs `All`:** same null mode, two labels — implemented exactly as drawn.
18. **Swipe commit threshold:** design's interactive deck commits at **92px** of drag
    (~⅓ card width). This overrides the 2026-07-27 "light flick" tuning (15% of screen
    ≈59px). One constant to flip back (`DISMISS_THRESHOLD_PX`).
19. **State chip on every card:** the interactive deck renders a neutral chip for
    non-started cards; the static frames show a chip only for `In progress`. Static frames
    win: chip only when in progress.
20. **Health chips ("Been a while"/"Skipped a lot")** aren't in the design frames. The
    don't-skip offer + triage queue absorb their job. Kept as muted chips on the card face
    (below the In-progress chip) so Story 7.2 behavior isn't silently lost — flag if you'd
    rather drop them.
21. **Corner info icon / review mode:** the design's card front has no review marker; review
    lives in triage + card-back guesses. The top-right corner tap now routes to the card
    back (same as pencil) when flagged; home review-mode banner is replaced by the triage
    queue. The old `Needs review` a11y target stays on flagged cards, pointing at triage.
22. **Micro-task nudge (E9):** tap fetches the smallest step, writes it as a step, and opens
    the working screen directly (no accept/dismiss chips). Errors fall back to the old
    inline retry. Skip-count threshold (5) and reset semantics unchanged.
23. **"Size switcher can slide away on scroll"** — home doesn't scroll; ignored.
24. **Soft gradient ground** — saved OFF; not implemented.
25. **Deck a11y:** the flattened top-card label formula stays, updated for new value model.

## Working screen

26. **Zero steps:** actions row shows only `Get more steps` (returns the first 3);
    `Change these` appears once steps exist. `Help me with this` and the proposal card are
    gone (auto-accept + Undo replace accept/reject). The `?breakdown=1` deep link now
    triggers `Get more steps` on arrival.
27. **NEW/CHANGED report line:** persists until the screen closes or the next AI action
    (not a timed toast). Frame copy `2 ADDED · 1 CHANGED` used (the prose said "rewritten").
28. **`ai.moreSteps`:** new procedure; the model decides append-3 vs subdivide-remaining and
    reports which; client diffs to place NEW tags. Step-count ceilings: total ≤ banking cap
    (5 quick / 10 big) is preferred but not enforced beyond the server's existing max of 10.
29. **Refine feedback length:** server caps at 500 chars — input enforces maxLength.
30. **Edit-mode drag** starts from the grip only (row body is the rewrite tap target).
31. **Delete undo** restores the row at its old index including completed state (paired
    ledger rows keep banking exact).
32. **Completion "card lifts and clears the top edge":** the working screen has no card —
    implemented as the toast + bloom + five-star burst over the pop back to home. Haptics
    deferred (expo-haptics is a native module → next APK rebuild; noted in backlog).
33. **Keyboard behavior** implemented per 05f with the **soft-fade** clip (saved
    listClipMode), not the inset-shadow cut shown as the frame default.

26b. **(D2 deferrals)** The bonus halo (static glow + sonar ripple) and the
    E5x mid-drag erosion float (the clay −N rising off the badge as the card
    leaves) are deferred to the D7 polish pass — Android colored-shadow
    limits need a bespoke Reanimated treatment; the gold band, border and
    tinted rail carry the state meanwhile. Erosion itself applies on every
    committed pass. The session auto-open grace window runs 4s (slow cold
    starts were silently forfeiting it at 1.5s).

## Card back

34. **Bottom actions are `Confirm all guesses` + `Done editing` only** — Start/Continue and
    Cut loose leave the back (deck tap opens the working screen, which owns terminal
    actions; cut-loose also lives in triage/task-list). The little ★ on Confirm-all hints
    the queue-clear star.
35. **`Confirm all guesses`** clears every remaining flag at once; it counts toward the
    triage queue-clear rule like individual confirms (no per-card star).
36. **Card-back entry animation** (flip?) unspecified — kept the existing overlay expand
    (220ms) restyled; no 3D flip invented.

## Brain dump

37. **The gate reverses current behavior** (today: parse saves immediately). Now nothing
    saves until `Add N tasks`. Backing out (`Back to the dump`, back arrow) discards the
    parse but keeps the dump text in the input.
38. **Server contract change:** parse returns per-task `evidence[]` + `unclaimed[]`;
    `feedback` re-parse and single-line `promote` added. Fake provider mirrors all three
    (line-per-task, first line = evidence, no unclaimed unless a line starts with "?").
39. **Evidence in the DB:** task rows don't store evidence; quotes exist only on the check
    screen (design shows them nowhere else). Details field still receives the AI's details.
40. **Row swipe-to-remove on the check screen:** implemented as the same dismiss gesture
    family as the deck (right/left fling); the × control does the same thing.

## Triage

41. **Queue = tasks with review items** (`hasCheckNeeded`), newest first; `Skip this one`
    moves to the queue's end without clearing flags. Welcome-back attention rows (deadline
    passed/stale/avoided) keep their existing separate screen for now — only the blueprint
    restyle applies there later; merging the two queues is a product call I didn't make.
42. **In-place title/details editing** with keyboard-over-ground; `done` return-key type.
43. **Triage entry badge** counts queued cards; button hidden when the queue is empty.

## Dark mode

45. **Dark values for undrawn screens** derived from the dark ground/ink mapping (spec §0).
46. **Triage in dark mode:** blueprint ground is already dark; unchanged between modes.
