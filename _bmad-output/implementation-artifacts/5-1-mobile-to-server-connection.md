# Story 5.1: Mobile-to-Server Connection

Status: ready-for-dev
Date: 2026-07-16
Mode: wave-based autonomous run (spec written up front; implementer reads ONLY this + CLAUDE.md + code)

## Story

As a user, I want my app to connect to the backend server, So that my data can be synced across devices (infrastructure for FR62–65).

## Local-mode strategy

The server runs on the host (`bun run server:dev`, port 3000). The Android emulator reaches the host loopback at **`10.0.2.2`** (works even for 127.0.0.1-bound ports). E2E runs the **release APK**, which by default blocks cleartext HTTP — this story must enable `usesCleartextTraffic` or the connection AC is untestable end-to-end.

## Acceptance Criteria

1. A tRPC client (`@trpc/client@11.17.0` + `@trpc/react-query@11.17.0` + `@tanstack/react-query@^5.101.0`) is configured with `AppRouter` imported **type-only** (`import type { AppRouter } from '@one-down/server'`) — a value import would force Metro to bundle Fastify/drizzle/postgres.js. Verify: release bundle builds and the app boots.
2. `getApiBaseUrl()`: `EXPO_PUBLIC_API_URL` env override wins; otherwise `http://10.0.2.2:3000` when `Platform.OS === 'android'`, else `http://localhost:3000`. (`EXPO_PUBLIC_*` is inlined at Metro bundle time — restart Metro / rebuild the APK after changing it.)
3. Single `httpBatchLink` at `${base}/trpc` with a `timeoutFetch` wrapper (5s `AbortController`, forwards an external `signal`'s abort). `QueryClient`: `retry: 1`, `staleTime: 30_000`. Client + QueryClient instantiated once via `useState` in `TrpcProvider`. **No transformer** (superjson lands symmetrically in 5.3).
4. `TrpcProvider` mounts in the root layout OUTSIDE `MigrationGate` (no dependency on SQLite readiness). Order this story: `GestureHandlerRootView → GluestackUIProvider → AppPostHogProvider → TrpcProvider → MigrationGate → Stack` (AuthProvider slots in outside TrpcProvider in 5.2).
5. On the home screen the app calls the tRPC `health` query and shows a subtle `ConnectionStatus`: states `checking` (query pending) → `connected` (`data.status === 'ok'`) → `offline` (query error). Accessible label `Server connection: <state>` (Maestro anchor). Offline state shows the UX-spec copy "Couldn't reach the server — working offline" inline; connected/checking states are a small unobtrusive dot only.
6. Release APK can talk cleartext HTTP: add `expo-build-properties` plugin with `android: { usesCleartextTraffic: true }` (android/ is gitignored and regenerated by `mobile:build`'s prebuild, so the plugin takes effect on the next build).
7. Offline behaviour is non-blocking: with the server down, the app works exactly as before (local-first) — no error modal, no crash.

## Implementation Plan

**Deps** (`bun add` in apps/mobile — pure JS, no expo install needed): `@trpc/client@11.17.0`, `@trpc/react-query@11.17.0`, `@tanstack/react-query@^5.101.0`; `npx expo install expo-build-properties`. Remember the gate-discipline rule: expo CLI rewrites package.json/tsconfig formatting — re-run `lint:check` last.

**apps/mobile/src/lib/api-url.ts** (new): `getApiBaseUrl()` per AC-2 (reads `process.env.EXPO_PUBLIC_API_URL`, `Platform.OS`). Kept separate from trpc.tsx so it's unit-testable without React.

**apps/mobile/src/lib/trpc.tsx** (new):
- `export const trpc = createTRPCReact<AppRouter>()` (type-only server import).
- `timeoutFetch(input, init)`: `AbortController` + 5s `setTimeout`; abort also when `init?.signal` aborts; clear timer in `finally`.
- `TrpcProvider({ children })`: `useState(() => new QueryClient({ defaultOptions: { queries: { retry: 1, staleTime: 30_000 } } }))`, `useState(() => trpc.createClient({ links: [httpBatchLink({ url: getApiBaseUrl() + '/trpc', fetch: timeoutFetch })] }))`, renders `trpc.Provider` + `QueryClientProvider`.

**apps/mobile/src/components/connection-status/connection-status.tsx** (new): two exports —
- `ConnectionStatusView({ status: 'checking' | 'connected' | 'offline' })`: presentational, NativeWind only. A 8px rounded dot (`bg-success-500` connected / `bg-background-400` checking / `bg-warning-400` offline) + offline-only text line "Couldn't reach the server — working offline" (`text-xs text-typography-500`). Container has `accessibilityLabel={'Server connection: ' + status}` and `accessibilityLiveRegion="polite"` (RN has no 'status' role).
- `ConnectionStatus()`: container calling `trpc.health.useQuery(undefined, { refetchOnWindowFocus: false })`, derives status (`isPending → checking`, `isError → offline`, else `connected`), renders the view.

**apps/mobile/src/app/index.tsx**: mount `<ConnectionStatus />` in the home screen top area (row under the TopBar, right-aligned; must not shift the card stack layout — absolute or a fixed-height slot).

**apps/mobile/src/app/_layout.tsx**: wrap per AC-4.

**apps/mobile/app.json**: add `["expo-build-properties", { "android": { "usesCleartextTraffic": true } }]` to plugins.

**apps/mobile/.env.example** (new, committed): document `EXPO_PUBLIC_API_URL` (unset = emulator default) — root .gitignore already un-ignores `.env.example`.

Gotcha carried from planning: `TrpcProvider` must not read anything from SQLite; and don't return `Date` objects from any procedure until 5.3 (no transformer).

## Analytics

No new domain events — this is infrastructure; network/health is not an app-semantic event, and screen views are PostHog built-ins. `events.ts` untouched.

## Testing Plan

- **Unit** (`src/lib/api-url.test.ts`): `getApiBaseUrl` branching — env override wins, android default `http://10.0.2.2:3000`, non-android default. Real non-trivial branching; the only pure logic this story adds. (No timeoutFetch test — it would test AbortController, i.e. the platform.)
- **Portable stories** (`connection-status.stories.tsx`): three stories for `ConnectionStatusView` (checking / connected / offline) — auto crash-free tests via the existing composeStories harness (RNTL v14: `await render`). No story for the container (needs a live tRPC provider — covered by E2E; do NOT mock useQuery just to assert a mock).
- **Maestro E2E** — `.maestro/51-story-5-1-server-connection.yaml` (numbering scheme for this run: `<epic><story>-story-...` avoids collisions with parallel epic specs):
  - Header comment: PREREQ — `bun run server:dev` running on the host (the wave's e2e batch starts it before the suite).
  - `runFlow: common/launch-app.yaml` → `extendedWaitUntil: visible: 'Server connection: connected'` (timeout 10000) → `takeScreenshot: .maestro/screenshots/5-1-server-connected` → sanity: 'Add task' visible (home intact), assertNotVisible 'Unhandled'/'error occurred'.
  - Offline state is NOT e2e-tested (would require stopping the server mid-suite); the stories cover its rendering.

## UX Notes

- Barebones-functional pass: no animation, gluestack defaults. Indicator must be genuinely subtle — ADHD-first home screen stays calm; the offline line uses the exact UX-spec copy above, no red, no modal (feedback pattern: inline, near source, never blocking).
- 5.3's sync indicator will take over the "pending/retrying" job; this dot only reports server reachability. Keep them visually distinct later — not this story's problem.

## Dependencies

- **Story 5.0** merged (AppRouter export, tRPC health procedure, server boots).
- Host server running for the E2E flow only; app must behave gracefully without it (AC-7).

## Out of Scope

- Retry/backoff logic beyond `retry: 1`; sync scheduling (5.3).
- iOS networking config (Android-only MVP).
